# 配置与常见问题

## 两种环境文件

| 文件                     | 加载者      | 用途                                                          |
| ------------------------ | ----------- | ------------------------------------------------------------- |
| `.env.local`             | Vite 前端   | 可选，复制 `.env.example`；只放非敏感前端选项                 |
| `.env.translation.local` | Node 服务端 | 复制 `.env.translation.example`；密钥、模型、持久化与采集选项 |

两个实际文件均被 Git 忽略。进程环境变量优先于服务端文件。请从项目根目录启动，修改配置后重启相应进程。`npm run demo` 强制使用 mock 数据，不受已有 `VITE_NEWS_PROVIDER=api` 配置影响。

`VITE_NEWS_PROVIDER=mock` 会影响正常 Vite 构建；退出演示后如真实模式仍显示演示，检查前端文件或终端环境是否保留了这个值，改回 `api`。密钥只能写入服务端文件或服务端进程环境，不能使用 `VITE_` 前缀。

## 真实模式需要哪些连接

- 浏览器连接本地前端与 API，真实新闻图片可能直接连接发布方图片域名。
- worker 连接 `server/sources.ts` 启用的公开来源和允许的文章/图片域名。
- 配置模型密钥后，标题、摘要或选中的公开正文会发送至 `https://api.deepseek.com/chat/completions`。未启用模型时不发送。
- 模型名可通过 `DEEPSEEK_MODEL` 设置。当前适配针对 DeepSeek JSON 输出与非思考请求；不保证任意 OpenAI-compatible 服务直接可用。更换供应商需要修改两个服务端适配器并运行测试。

## 首次启动、空内容与来源异常

首次运行会在 `NEWS_DATA_DIR` 建库并获取 RSS，尚未发布批次时 API 返回 503。先检查 `npm run dev` 的采集日志，稍后点击重新加载。没有密钥时仍采集报道，但英文需手动选择“也显示未翻译原文”；AI 速读不会自动生成。

来源请求失败会保留旧内容。没有任何可用来源时，旧批次不会被空结果替换。可检查：

- `http://127.0.0.1:8787/api/health`：只表示 HTTP 服务活着。
- `http://127.0.0.1:8787/api/status`：来源状态、地区覆盖、任务和速读情况、额度。总体未 stale 不表示每个来源都正常。
- 新闻页面时间窗口、关键词、栏目和来源筛选是否限制了结果。

不要通过复制作者的历史 `data/` 来解决空库，也不要同时运行 `dev` 与第二个 `news:worker`。`news:refresh`、`news:translate`、`news:briefs` 是维护命令，运行前停止常驻 worker；后两个手工命令不受主队列每日额度保护。

## 端口与环境

演示可用 `npm run demo -- --port 5174`。真实开发模式的前端代理默认指向 `127.0.0.1:8787`；若改变 API 的 `PORT`，同步修改 `vite.config.ts` 的代理目标。生产前后端同源，无需这个开发代理。

若地球黑屏，先检查桌面浏览器 WebGL 和硬件加速、控制台错误、`/textures/earth-blue-ocean-8k.jpg` 是否能从本机加载。当前未提供 WebGL 不可用时的二维地图替代。

`npm ci` 网络失败属于依赖安装问题，请先确认 npm registry 的可达性。Node 低于 22.12 不支持本项目要求；推荐 Node 24。使用 ZIP 下载时也必须先解压，再在含 `package.json` 的目录执行命令。

## 持久化、额度和锁

`NEWS_DATA_DIR` 默认 `data`，包含 PGlite、快照、译文、速读和每日备份。`.gitignore` 只保证默认路径不提交；自定义数据目录应放在仓库外，或自行补充忽略规则。

`NEWS_DAILY_AI_ATTEMPTS=200` 以北京时间计数，`0` 延迟新增模型任务。已有缓存仍可读。失败模型请求计一次，缓存命中、锁忙、无法提取正文不计次。额度不是 token 或账单的精确金额，费用需结合提供商账单判断。

应用使用本机独占锁防止两个 worker 同写。正常退出自动释放，进程异常退出后可恢复。历史空锁或损坏标记不会被自动抢占；先确认无相关进程，备份数据后再由维护者处理，禁止对仍在运行的数据库删除锁文件。
