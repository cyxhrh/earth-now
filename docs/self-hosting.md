# 可选自部署与备份

本地演示与源码使用不需要购买服务器。本页仅供自行托管者，当前 V1 是单机架构，不提供作者托管的公共 API。

## 生产模式

安装 Node 24，下载源码，然后：

```sh
npm ci
npm run build
```

复制 `.env.translation.example` 为 `.env.translation.local`，填入自己的配置。确认前端没有 `VITE_NEWS_PROVIDER=mock`，然后运行 `npm run start:all`。默认网站/API 在 `http://127.0.0.1:8787`。

前端与 API 同源；反向代理把域名的 HTTPS 请求转发到 `127.0.0.1:8787`。仅代理端口对外，默认保持 Node 监听回环地址。对 `/api/status` 限制访问者，因为它包含来源状态与内部运行统计。配置证书续期、进程守护、日志轮转和磁盘监测后再公开运行。不要将源码根目录或 `data/` 配置成公开静态目录。

API 命令为 `npm start`，后台命令为 `npm run news:worker`，二者可以由你的 systemd / 进程管理工具分别守护。一个部署仅启动一个 worker；如果已运行 `start:all`，不要另开 `news:worker`。

静态演示只需 `npm run build:demo` 的 `dist/`，但资源路径当前以网站根目录为准。部署到 GitHub Pages 仓库子路径前需适配资源基路径；不能直接把真实模式构建交给 Pages 期待后台工作。

## 数据与迁移

把 `NEWS_DATA_DIR` 指向持久化目录，发布新代码时不要覆盖或清空它。默认 PGlite 数据库同机独占；独立 PostgreSQL 可通过 `DATABASE_URL` 接入，但 API 与 worker 仍须共享快照和翻译/速读缓存目录，不支持任意多机部署。

修改数据库连接不会自动迁移数据。采用逻辑备份恢复到空库；不要复制正在写入的 PGlite 目录，也不要同时让两个进程使用它。

## 备份与恢复

worker 每个北京时间日期首次循环写入 `data/backups/YYYY-MM-DD.json`，包含报道、历史、任务、额度和生成缓存，不包含模型密钥。把备份另存一份到独立设备；同一磁盘副本不能防磁盘丢失。当前备份不自动淘汰，维护者应制定保留期并监测空间。

恢复步骤：

1. 停止 worker，保留现有数据。
2. 在服务端配置中把 `NEWS_DATA_DIR` 改为一个新的空目录，例如 `data-restore`；不要让它意外加入 Git。
3. 执行 `npm run news:restore -- <备份文件的实际路径>`。
4. 检查发布快照、条目数、译文和速读，再用相同目录重启 API 与 worker。

恢复工具会拒绝非空数据库。外部 PostgreSQL 的连接与权限、异机迁移及线上负载需自行验证；项目不会自动替你创建云数据库。

## 公共服务边界

来源可达不等于可以自由转载文章与图片。开源许可证覆盖本项目代码，不为使用者授予新闻内容或商标权利。公开运营时，请按所在地、受众和内容范围核实来源许可及适用要求；保留来源署名、发布时间、AI 整理标识和原文入口。
